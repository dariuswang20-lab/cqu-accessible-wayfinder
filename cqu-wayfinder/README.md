# 知路 · 重庆大学无障碍寻路交互原型

这是《人机交互与人工智能》课程的空间智能产品原型。网站使用静态 HTML、CSS、JavaScript，可直接在浏览器运行；`dist/` 是部署目录。

## 场景与边界

- 重点案例：重庆大学 B 校园第二综合楼。
- A 校园主教学楼、C 校园第一教学楼作为可迁移的场景入口，当前共用一套**示意楼层图**。
- 校园照片来自重庆大学官网：A/B <https://www.cqu.edu.cn/zjzd/gyzd/hp_zd/1.htm>；C <https://www.cqu.edu.cn/zjzd/gyzd/hp_zd.htm>。
- 楼内节点、设施、动线、距离、电梯与封闭状态均为研究用模拟数据，**不能作为实际导航或疏散依据**。若用于实地场景，须取得并核验平面图、入口坡度、门宽、电梯状态、设施位置和开放时间。

## 原型功能

用户选择起点、目的地、通行方式和路线偏好；节点图最短成本搜索据此推荐路线。轮椅模式排除楼梯；用户可以模拟电梯停用、走廊封闭和拥挤，比较替代路线，查看系统的推荐理由。当无台阶通路不可达时，界面如实显示不可达。

## 课程研究方案

- 主要用户：有无台阶通行需求的学生、教职工和访客。次要用户：陪同者、楼宇管理人员。
- 研究问题：在校园教学楼寻路中，解释推荐理由是否提高用户对路线建议的信任？
- 假设 H1：相比仅展示路线，展示推荐理由的组别信任评分更高。
- 自变量：解释展示条件（A 组仅路线；B 组路线与解释）。
- 因变量：1–5 分信任评分。辅助指标：任务完成、完成时长、清晰度、控制感评分。
- 任务：选择无台阶，从南入口到 205 教室，模拟中央至东廊连接通道封闭，判断是否有可行路线。主持人先设置实验条件，点击“开始测试任务并计时”。
- 建议测试至少 10 名真实最终用户，条件交替分配；记录匿名编号。测试主持人应统一任务说明，并确保 A 组不提前阅读 B 组解释。
- 原型的短问卷仅选取与课程要求相关的维度，不是完整 HuCAS 量表。正式报告可结合附录量表和访谈补充。
- 浏览器本地存储保存记录；CSV 导出用于报告。不同设备的数据不会自动汇总。严禁将模拟记录写成真实用户数据。

## 数据结构与后续实地化

`dist/app.js` 中 `nodes` 表示空间位置，`edges` 表示可通行连接及示意距离。真实落地时，需要对每个建筑提供版本化地图数据，并接入经授权、可核验的障碍状态和反馈审核流程。对外提供导航前，应建立设施维护责任人和现场核查机制。
